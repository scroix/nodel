# Jython to GraalPy recipe compatibility

This matrix is for recipe authors moving from the stock Nodel 2.2.x host to
Nodel 3.x on GraalPy. The stock baseline is
[`v2.2.1.542`](https://github.com/museumsvictoria/nodel/releases/tag/v2.2.1.542),
the release exercised by the v3
[wire-compatibility job](.github/workflows/compatibility.yml#L31-L35). The v3
column describes the current `v3` branch.

Wire compatibility does not make Python source compatible: 2.2.x and v3 hosts
can bind to each other, but a recipe moved onto v3 must use Python 3 syntax and
the runtime rules below.

| Surface | Stock Jython host (2.2.x) | GraalPy host (v3) | Code and test evidence |
|---|---|---|---|
| Language and syntax | Jython `2.5.4-rc1`, using Python 2.5 syntax: `print 'x'`, `iteritems()`, `/` integer division for integers, `except Exception, e`, and `unicode`/`basestring`. | GraalPy `25.2.4`, using Python 3 syntax: `print('x')`, f-strings (`%` formatting still works), `items()`, `//` for integer division, `except Exception as e`, and `str`. Python-2-only source must be ported. | [Stock dependency](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/build.gradle#L75-L80); [v3 dependency](nodel-jyhost/build.gradle#L14-L14); [Python 3 examples](recipes/python3/README.md) |
| Declarative bindings | `local_action_`, `local_event_`, `remote_action_`, `remote_event_`, and `param_` names are discovered from the Jython namespace. | The same prefixes and metadata dictionaries are discovered. Saved parameters are injected before `main()`, and event/action placeholders become live objects with `.emit()`/`.call()`. | [Stock extractor](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/java/org/nodel/jyhost/BindingsExtractor.java#L47-L126); [v3 extractor](nodel-jyhost/src/main/java/org/nodel/jyhost/BindingsExtractor.java#L83-L128); [metadata tests](nodel-jyhost/src/test/java/org/nodel/jyhost/BindingsExtractorTest.java#L31-L67) |
| Binding decorators and helpers | `@local_action`, `@remote_event`, `LocalEvent`, `RemoteAction`, `Parameter`, and the `create_*` helpers are available. | The author-facing names and call shapes remain available. Decorated zero-argument handlers are still adapted to the one-argument binding call. | [Stock toolkit](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L217-L266); [v3 toolkit](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L247-L299); [REST binding test](nodel-jyhost/src/test/java/org/nodel/FunctionStyleBindingTests.java#L21-L84) |
| Managed toolkit helpers | `Timer`, `TCP`, `UDP`, `SSH`, `Process`, `quick_process`, and HTTP through `get_url`/`getURL` wrap the managed Java toolkit. There is no separate `HTTP()` constructor. | The same helpers and legacy camelCase call shapes are retained. For example, use `firstDelayInSeconds`, `setInterval()`, and `getInterval()` on `Timer`. | [Stock helpers](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L89-L199); [v3 helpers](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L179-L382); [toolkit parity tests](nodel-jyhost/src/test/java/org/nodel/jyhost/ToolkitGlobalsTest.java#L88-L152); [HTTP/process tests](nodel-jyhost/src/test/java/org/nodel/jyhost/ToolkitGlobalsTest.java#L167-L228) |
| JSON | `json_encode()` and `json_decode()` delegate to the Java toolkit. | The names are unchanged. v3 normalises GraalPy dicts, lists, strings, numbers, booleans, and `None`, including nested values, across the guest/Java boundary. Do not depend on the exact encoded text for a top-level string; round-trip semantics are the compatibility contract. | [Stock wrappers](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L31-L37); [v3 wrappers](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L375-L382); [round-trip tests](nodel-jyhost/src/test/java/org/nodel/jyhost/GraalPyJsonRoundTripTest.java#L16-L130) |
| Java interop | Jython exposes Java packages directly, so recipes commonly use imports such as `from org.nodel... import ...`. | Prefer `import java` then `Type = java.type('fully.qualified.Type')`. A compatibility import hook covers `org`, `java`, `com`, and `javax` package imports, but direct static-method imports from a Java class are not portable; resolve the class and call the member instead. | [Stock Java imports](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L344-L350); [v3 import hook](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L12-L96); [`java.type` tests](nodel-jyhost/src/test/java/org/nodel/jyhost/GraalVMContextTest.java#L128-L180) |
| Lifecycle hooks | `@before_main`, `main()`, and `@after_main` run in that order; `@at_cleanup` runs on restart or shutdown. | The same decorators and order are retained. Cleanup failures are written as console warnings rather than silently discarded. | [Stock decorators](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L292-L342); [v3 decorators](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L478-L519); [v3 host order](nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L492-L527) |
| Console and tracebacks | `console.log/info/warn/error` and interpreter stdout/stderr feed the node's web console. Errors use Jython exception formatting. | The same `console` methods work, including the legacy `console.instance` pattern, and `print()` is line-buffered into the web console. Guest errors use CPython-style tracebacks with file, line, function, and syntax-error location, so exact traceback text differs. | [Stock console](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L20-L37); [v3 console shim](nodel-jyhost/src/main/resources/org/nodel/jyhost/nodetoolkit.py#L98-L135); [stdout/stderr bridge](nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L635-L707); [traceback renderer](nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L765-L855) |
| REPL (`eval` / `exec`) | `eval` evaluates one Python 2 expression and returns its value; `exec` runs a Python 2 code fragment without echoing an expression result. Both operate in the live node namespace. | The REST services and live-namespace behaviour remain. Grammar is Python 3. `eval` returns the expression value; `exec` first tries the input as an expression and writes a non-null result to the console, then falls back to statement execution only on `SyntaxError`. | [Stock services](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L1434-L1513); [v3 services](nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L1221-L1345); [concurrent eval/exec test](nodel-jyhost/src/test/java/org/nodel/jyhost/PyNodeThreadingTest.java#L194-L224) |
| `.pysp` server pages | `.pysp` files are routed to the Jython template engine, and each node receives an `_example.pysp`. | A GraalPy handler remains in the v3 source, but no automated v3 test covers it. Do not treat it as a compatibility promise: migrate server-side behaviour to REST services or static content before upgrading. | [Stock routing](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/java/org/nodel/jyhost/NodelHostHTTPD.java#L417-L430); [stock example generation](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/nodel-jyhost/src/main/java/org/nodel/jyhost/PyNode.java#L590-L602); [v3 legacy handler](nodel-jyhost/src/main/java/org/nodel/jyhost/NodelHostHTTPD.java#L403-L526) |
| Runtime and packaging | The release is a JAR that bundles Jython and runs on a stock Java 11+ runtime. | The standalone JAR requires the matching GraalVM Community `25.2.4` / JDK `25.0.4`; stock OpenJDK is unsupported. Self-contained Linux x64/arm64, macOS arm64, and Windows x64 app images bundle that runtime and need no installed Java. App images are the recommended deployment; Native Image remains experimental. | [Stock runtime](https://github.com/museumsvictoria/nodel/blob/v2.2.1.542/README.md#L103-L127); [v3 toolchain](build.gradle#L65-L71); [app-image build](nodel-jyhost/build.gradle#L210-L305); [platform matrix](.github/workflows/package.yml#L23-L46); [java-less and standalone smoke](.github/workflows/package.yml#L67-L161) |
| Nodel wire protocol | Stock hosts discover peers and exchange remote actions/events over Nodel's existing protocols. | v3 remains wire-compatible: the scheduled smoke test runs a stock Jython host and a v3 host side by side and checks action/event round trips in both directions. This does not remove the source-porting requirements above. | [Cross-host fixtures and assertions](scripts/compat-smoke.sh#L77-L220); [scheduled CI gate](.github/workflows/compatibility.yml#L1-L35) |

## Working Python 3 examples

Start with the examples under [`recipes/python3/`](recipes/python3/README.md):

- [`tcp-device`](recipes/python3/tcp-device/script.py) shows `Parameter`,
  `LocalEvent`, `@local_action`, and the managed `TCP` helper.
- [`scheduler`](recipes/python3/scheduler/script.py) shows `Parameter`,
  `LocalEvent`, `@local_action`, and the legacy-compatible `Timer` API from a
  Python 3 recipe.

Copy either folder into the host's `nodes/` directory and follow the
[REST examples](recipes/python3/README.md#trying-them) to exercise it. Keep the
binding and toolkit names shown there; port the surrounding Python syntax and
Java imports rather than rewriting the Nodel interaction model.
